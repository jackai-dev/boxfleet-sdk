# BoxFleetSdk

Executable .NET 8 SDK generated by OmniWrap from the semantic contract for
`BoxFleet`.

```csharp
using BoxFleet.Sdk;
using var client = new ApiClient(options: new ClientOptions {
    BaseUrl = new Uri("https://boxfleet.io"),
    ApiKey = Environment.GetEnvironmentVariable("API_KEY"),
    AccessToken = Environment.GetEnvironmentVariable("ACCESS_TOKEN"),
});
```

The client accepts an injected `HttpClient`, cancellation tokens, API key,
Bearer and Basic authentication, JSON, multipart/form-data, form-urlencoded,
text and binary bodies, OpenAPI `style`/`explode` parameter serialization,
default and per-request headers, timeouts, server-guided retries for idempotent
operations and for any request that carries an `IdempotencyKey` (see
Retries), typed exceptions per status
(`NotFoundException`, `RateLimitException`, ... all deriving from
`ApiClientException`), raw-response overloads (`XxxWithResponseAsync`) that
expose status, headers and request id, bounded server-sent-event and NDJSON
streaming, and a streaming-enforced response limit configurable from 1 byte
through 64 MiB for buffered responses.

## Retries

`MaxRetries` (default 2, per call `RequestOptions.MaxRetries`) bounds the
attempts. A request is retried only when its operation is idempotent or it
carries an `Idempotency-Key`; connection failures and timeouts follow the same
rule. The key can come from `ClientOptions.DefaultHeaders`, an operation's
declared `Idempotency-Key` header parameter, `RequestOptions.Headers`, or
`RequestOptions.IdempotencyKey`. These layers apply in that order, so request
headers override declared and default headers. A nonblank
`RequestOptions.IdempotencyKey` is applied last and overrides the headers unless
the operation has a nonblank declared key parameter; that declared parameter
suppresses the option value. If `RequestOptions.Headers` also supplies the key,
its value remains in that case. Every attempt replays the resulting key. The server's own
verdict wins: `x-should-retry: true` or `false` overrides the status policy
(408, 409, 429 and every 5xx), and its wait is
honoured from `retry-after-ms`, then `Retry-After` (seconds or an HTTP-date),
then an IETF `RateLimit` reset (`t=` or `RateLimit-Reset`). Without one, waits
back off exponentially with jitter (0.5 s doubling, at most 60 s). A server
asking for longer than `MaxRetryDelay` (default 60 s) gets its error surfaced
at once, with its headers and `Retryable` flag, since a retry it said would
fail only adds load; `RetryBudget` caps a whole call, waits included.

`FallbackBaseUris` lists ordered alternates to `BaseUrl`. Only idempotent
operations use them, and only a connection failure, a timeout or a 5xx moves a
call to the next one; a 4xx retry such as a 429 stays on its endpoint, and the
last endpoint serves the remaining attempts. `OnAttempt` is awaited after
every attempt with an `AttemptContext` naming the `BaseUrl` it targeted, the
`RequestUri`, the `StatusCode` or connection `Error`, and the `RetryDelay`
before the next attempt, if any. A declared response length above
`MaxResponseBytes` still reports the endpoint and response status before the size
exception propagates. The lifecycle hooks and the tracer are described under
Hooks and tracing.

```csharp
using var client = new ApiClient(options: new ClientOptions {
    BaseUrl = new Uri("https://boxfleet.io"),
    MaxRetries = 3,
    RetryBudget = TimeSpan.FromSeconds(20),
    FallbackBaseUris = new[] { new Uri("https://eu.example.com") },
    OnAttempt = (attempt, _) => { Console.WriteLine($"{attempt.BaseUrl} {attempt.StatusCode}"); return Task.CompletedTask; },
});
```

## Hooks and tracing

`ClientOptions.Hooks` (a `RequestHooks`) observes every call. Each attempt
starts with `BeforeRequest` and ends with exactly one of `OnRetry` (another
attempt follows), `AfterResponse` (the success the call returns) or `OnError`
(the failure the call throws): a call that succeeds after one retried 503
reports `BeforeRequest`, `OnRetry`, `BeforeRequest`, `AfterResponse`, and a
connection failure that is not retried reports `BeforeRequest`, `OnError`.
Each hook receives a `HookContext` record with `OperationId`, `Method`, `Url`,
`Headers`, `Attempt` (from 1), `Elapsed` since the call started, `StatusCode`
once the server answered, `Error` when the attempt or the call failed and
`RetryDelay` on `OnRetry`; each connection of a stream is one call.

The context is an immutable record: no hook can change the request. It never
carries a credential: `Authorization`, `Proxy-Authorization`, `Cookie`, every
API-key header and every API-key query parameter read `[redacted]` in
`Headers` and `Url`, and so does every configured credential value found
anywhere else. A hook's own exception ends the call with it.

`ClientOptions.Tracer` opens one span per call through the `IRequestTracer`
interface this SDK defines, with no tracing dependency: `StartSpan(operationId,
attributes)` receives `http.request.method`, and the returned `ITraceSpan` is
ended with `http.request.resend_count` (the retries) and, when the server
answered, `http.response.status_code`. OpenTelemetry .NET listens to
`System.Diagnostics.ActivitySource`, which ships with .NET, so this adapter needs
no package; register the source with `AddSource("my-service")` on your tracer
provider:

```csharp
using System.Diagnostics;

public sealed class ActivitySourceTracer : IRequestTracer
{
    private readonly ActivitySource _source;

    public ActivitySourceTracer(ActivitySource source) => _source = source;

    public ITraceSpan StartSpan(string name, IReadOnlyDictionary<string, object> attributes)
    {
        var activity = _source.StartActivity(name, ActivityKind.Client);
        foreach (var (key, value) in attributes) activity?.SetTag(key, value);
        return new Span(activity);
    }

    private sealed class Span : ITraceSpan
    {
        private readonly Activity? _activity;

        public Span(Activity? activity) => _activity = activity;

        public void End(IReadOnlyDictionary<string, object> attributes)
        {
            foreach (var (key, value) in attributes) _activity?.SetTag(key, value);
            _activity?.Dispose();
        }
    }
}

public static class ObservedClient
{
    public static ClientOptions Options() => new ClientOptions {
        Tracer = new ActivitySourceTracer(new ActivitySource("my-service")),
        Hooks = new RequestHooks {
            OnRetry = context => Console.WriteLine($"{context.OperationId} {context.Attempt} {context.StatusCode}"),
        },
    };
}
```

## Streaming

Operations whose contract declares the `sse` streaming trait return
`IAsyncEnumerable<SseEvent<T>>`; each event exposes `Data`, `Id`, `Event` and
`Retry` (milliseconds), the incremental UTF-8 frame parser tolerates CRLF, LF
and CR delimiters, comment lines and multi-line `data`, and a `data: [DONE]`
frame ends the stream. Operations declaring `ndjson` return
`IAsyncEnumerable<T>`, one decoded value per bounded line.

`StreamOptions` bounds every stream: `MaxReconnects` (0 through 1000, default
0), `ReconnectDelay` (0 through 60 s, replaced by a server `retry` field),
`LastEventId`, an `OnReconnect` hook and `MaxLineLength`. A `Last-Event-ID`
header is sent only when the stream URL shares the configured base URL's
origin, and out-of-range options raise `StreamingException` before any request
is sent. Disposing the enumerator, or cancelling the `CancellationToken`, closes
the connection without reconnecting. A streamed body is not covered by
`ClientOptions.Timeout` -- that deadline ends once the response headers arrive
-- so a long-lived stream is bounded by the caller's `CancellationToken`.

## Models and serialization

Object and `allOf` schemas become nullable-aware records; arrays, maps and enums
(component and inline) remain typed; `const` members are defaulted literals;
`oneOf` with a discriminator becomes an abstract record with sealed variants and
a discriminator-driven converter. Remaining `oneOf`/`anyOf` values use lossless
`JsonElement`. JSON metadata for every generated model is source-generated
(`OmniWrapJsonContext`); the reflection resolver stays as a fallback, so the
package is not declared AOT-compatible. Operations with validated
cursor, offset, or page plans also expose bounded `XxxPagesAsync` enumeration;
unproven traits remain ordinary one-page operations.
