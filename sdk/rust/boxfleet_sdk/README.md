# BoxFleet

Native Rust 2021 SDK generated by OmniWrap semantic IR 1.14.0.

Minimum supported Rust version (MSRV): 1.86. `Cargo.lock` pins the complete
148-package resolution used by OmniWrap's verification gates; dependency
updates require regenerating and requalifying that curated lock template.

## Usage

```rust,ignore
use boxfleet_sdk::{Client, ApiError};

#[tokio::main]
async fn main() -> Result<(), ApiError> {
    let client = Client::builder()
        .bearer_token(std::env::var("API_TOKEN").unwrap_or_default())
        .max_retries(3)
        .build()?;
    let result = client.get_health(/* arguments */ None).await?;
    println!("{result:?}");
    Ok(())
}
```

`Client::builder()` starts from the contract's default server; `server_url(index,
&[("variable", "value")])` resolves any declared server template. `Client` is
`Clone + Send + Sync` and shares its connection pool across clones.

## Behaviour

- Authentication: named API keys, bearer/OAuth/OpenID tokens, Basic, and
  preconfigured mTLS clients, applied per operation security requirement.
- Retries: idempotent operations and requests carrying an `Idempotency-Key`
  retry transient statuses and transport failures under the server's guidance
  (see Retries below).
- Errors: `ApiError` is an enum (`Status`, `Timeout`, `Transport`, `Decode`,
  `Authentication`, `Configuration`, `Pagination`, `Streaming`, `ResponseTooLarge`) with accessors for status,
  headers, decoded body, typed error schema, request id, and attempt count;
  `std::error::Error::source()` exposes the underlying transport error.
- Response metadata: each decoded operation has an `op_with_response` sibling
  returning `ApiResponse<T>` with status, headers, request id and decoded value;
  the original `op` returns only `T`. Buffered success and error bodies are
  limited to 8 MiB by default. Set `ClientBuilder::max_response_bytes` or
  `RequestOptions::max_response_bytes` to change the bound; exceeding it returns
  `ApiError::ResponseTooLarge` without buffering beyond the limit. For example:
  `let response = client.get_health_with_response(/* arguments */ None).await?;`
  then inspect `response.status`, `response.headers`, `response.request_id` and
  `response.value`.
- Models: `allOf` compositions are flattened into one struct, discriminated
  `oneOf` unions dispatch on the discriminator, string enums keep unknown wire
  values in an `Unknown(String)` variant, and optional nullable fields preserve
  absent, explicit `null`, and present states.
- Streaming: server-sent-events operations return `EventStream<T>` and NDJSON
  operations return `NdjsonStream<T>`; pull with `.next().await`, or call
  `into_stream()` for a `futures_core::Stream`. Each `SseEvent` carries `data`,
  `id`, `event` and `retry`; frames tolerate CRLF, LF and CR delimiters, comment
  lines and multi-line `data`, and `[DONE]` ends the stream. `RequestOptions::stream`
  (`StreamOptions`) bounds resumption: `max_reconnects` (0-1000, default 0),
  `reconnect_delay` (at most 60 s, replaced by a server `retry`), an
  `on_reconnect` hook, `max_event_bytes` and `max_line_length`, all refused
  before any request when out of range. A resumption replays the first request
  with the last `id` as `Last-Event-ID`, which, like `RequestOptions::last_event_id`,
  is only sent to the client's own endpoints (`base_url` and its fallbacks), the
  resumption to the one that served the stream; a multipart body cannot be replayed and
  never resumes. Dropping a stream cancels its in-flight request, and the
  per-request timeout also bounds how long one stream may run.
- Pagination: cursor/offset/page traits produce `Page<T>` results and a
  `<Operation>Pages` walker with `next_page()` and `collect_pages()`.
- Dropping an operation future cancels the in-flight request.

## Retries

`ClientOptions::max_retries` (default 2, per call `RequestOptions::max_retries`)
bounds the retries after the first attempt. A request is retried only when its
operation is idempotent or it carries an `Idempotency-Key` header: a declared
`Idempotency-Key` parameter, one in `RequestOptions::headers` or a default
header. A declared parameter the caller sets wins over the same header in
`RequestOptions::headers`, and every attempt replays the key the first one sent.
Transport failures and timeouts follow the same rule. The server's own
verdict wins: `x-should-retry: true` or `false` overrides the status policy
(`408`, `409`, `429` and every `5xx`; `425` is never retried), and its wait is
honoured from `retry-after-ms`, then `Retry-After` (seconds or an HTTP-date),
then the IETF `RateLimit` reset (`t=` or `RateLimit-Reset`). Without one, waits
back off exponentially with jitter (0.5 s doubling, at most 60 s). A server
asking for longer than `max_retry_delay` (default 60 s) gets its error returned
at once, with its headers and `retryable()` flag, rather than an early retry it
said would fail; `retry_budget` (default none) caps a whole call, waits
included.

`fallback_base_urls` (default none; `ClientBuilder::fallback_base_url` appends
one) lists ordered alternates to `base_url`.
Only idempotent operations use them (a key makes a retry safe on the same
endpoint, not on another one), and only a transport failure, a timeout or
a `5xx` moves a call to the next one; a `4xx` retry such as a `429` stays on its
endpoint, and the last endpoint serves the remaining attempts. A server-sent
events resumption goes back to the endpoint that served the stream. The
`on_attempt` hook runs after every attempt with an `AttemptInfo` naming the
`base_url` and `url` it targeted, the `status` or transport `error`, and the
`retry_delay` before the next attempt, if any; `ApiResponse::base_url` names the
endpoint that served a decoded response.

```rust,ignore
let client = Client::builder()
    .max_retries(3)
    .retry_budget(std::time::Duration::from_secs(20))
    .fallback_base_url("https://eu.example.com")
    .on_attempt(|attempt| println!("{} {:?}", attempt.base_url, attempt.status))
    .build()?;
```

## Hooks and tracing

`ClientBuilder::hooks(RequestHooks::new()...)` observes every call. Each attempt
starts with `before_request` and ends with exactly one of `on_retry` (another
attempt follows), `after_response` (the success the call returns) or `on_error`
(the error the call returns): a call that succeeds after one retried 503
reports `before_request`, `on_retry`, `before_request`, `after_response`, and a
connection failure that is not retried reports `before_request`, `on_error`.
Each hook borrows a `HookContext` with `operation_id`, `method`, `url`,
`headers`, `attempt` (from 1), `elapsed` since the call started, `status` once
the server answered, `error` when the attempt or the call failed and
`retry_delay` on `on_retry`; each connection of a stream is one call.

The context is an owned copy: no hook can change the request. It never carries a
credential: `Authorization`, `Proxy-Authorization`, `Cookie`, every API-key
header and every API-key query parameter read `[redacted]` in `headers` and
`url`, and so does every configured credential value found anywhere else,
including in a transport error's text.

`ClientBuilder::tracer` opens one span per call through the `RequestTracer`
trait this crate defines, with no tracing dependency: `start_span` receives the
operation id and `http.request.method`, and the returned `TraceSpan` is ended,
when the call returns, with `http.request.resend_count` (the retries) and, when
the server answered, `http.response.status_code`. With the `opentelemetry`
crate in your project, this adapter maps it onto OpenTelemetry:

```rust,ignore
use boxfleet_sdk::{RequestTracer, SpanValue, TraceSpan};
use opentelemetry::global::BoxedSpan;
use opentelemetry::trace::{Span, Tracer};
use opentelemetry::KeyValue;

struct OpenTelemetryTracer;

struct OpenTelemetrySpan(BoxedSpan);

fn key_values(attributes: &[(&'static str, SpanValue)]) -> Vec<KeyValue> {
    attributes
        .iter()
        .map(|(key, value)| match value {
            SpanValue::Text(text) => KeyValue::new(*key, text.clone()),
            SpanValue::Int(number) => KeyValue::new(*key, *number),
        })
        .collect()
}

impl RequestTracer for OpenTelemetryTracer {
    fn start_span(&self, name: &str, attributes: &[(&'static str, SpanValue)]) -> Box<dyn TraceSpan> {
        let mut span = opentelemetry::global::tracer("my-service").start(name.to_owned());
        span.set_attributes(key_values(attributes));
        Box::new(OpenTelemetrySpan(span))
    }
}

impl TraceSpan for OpenTelemetrySpan {
    fn end(mut self: Box<Self>, attributes: &[(&'static str, SpanValue)]) {
        self.0.set_attributes(key_values(attributes));
        self.0.end();
    }
}
```

Register it with `Client::builder().tracer(OpenTelemetryTracer)`, beside
`.hooks(RequestHooks::new().on_retry(|context| println!("{} {} {:?}", context.operation_id, context.attempt, context.status)))`.
